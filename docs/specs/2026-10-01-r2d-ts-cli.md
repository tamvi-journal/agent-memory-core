# R2d: TypeScript owner CLI

Status: settled by Lam's review @ 9bdfbbb (Q1 changed, Q2–Q6 yes, F1–F7 applied; §6). Author: Aux (leader). Builds on R0, R2a, R2b and R2c.

## 0. Goal, scope, dependency

R2d gives `@trajecta/identity` a command-line entry point that can stand in for `trajecta_identity/cli.py` (`trajecta-identity`). Python stays the oracle. As in R2c, the port must first **define** what the Python CLI does today (§1). Two semantic oracle patches, P10 (`doctor`) and P13 (deterministic public CLI errors), then fix the places where that behavior is unsafe or undefined, in both runtimes. P11 and P12 are frozen, test-only invariants. The TS port follows the patched oracle.

**F0 — dependency.** R2d starts from a `main` that contains PR #18 (65e374d). The CLI reuses the R2c `IdentityMemory`, profile loading, `pythonIndentedJson` and the error classes. It must not fork them.

**In scope (Q1 = split)**
- Entry point `node --experimental-strip-types node/src/cli.ts [-p PROFILE] [--db PATH] COMMAND …`, with no dependencies.
- Profile resolution (`recipe.resolve`): name, folder, `.json` file, `http(s)` URL; `$TRAJECTA_IDENTITY_PROFILE`; `.last-profile`; default `example`.
- Paths: `data_dir`, `safe_fs_name`, `profile_db`, `profile_search_dirs`.
- Commands: `init`, `setup`, `profiles`, `work`, `status`, `retrieve`, `log-phase`, `log-fact`, `timeline`, `decay`, `core-proposals`, `approve-core`, `approve-retract`, `close-legacy-discussion`, `apply-receipt`, `close-loop`, `migrate-to`, and the new `doctor` (P10).

**Out of scope**
- **R2e (Q1):** `view` (HTTP server and page) and `plugin` (bundle builder). Each is a separate surface with its own I/O (sockets, zip), and neither is on the cutover path.
- **`import-aml`:** stays Python-only through R3 (R2b Q6 settlement). R4 decides whether to ship, archive or port it. It is one-shot import tooling, not product write law.
- **R3:** cross-runtime runs, fuzzing (carry: present-null or non-string evidence metadata at the kernel, and `source_ref` null), migration rehearsal on a copy of a real store.
- **R4:** installer, `bin` launcher, cutover, and the single version source (carry: pyproject 0.4.0 vs runtime/wire 0.1.0).
- G1–G12 stay frozen. G6 is fixed on the CLI path by P10 (`doctor`) and P11 (reads).

## 2. Oracle patch and frozen invariants (both runtimes)

**P10 — `doctor` that never initializes.** New command `doctor`.
- It resolves the profile with `remember_choice=False`, so it never writes `.last-profile`.
- Its read-only guarantee covers the **memory store**: it never creates, migrates or bootstraps the store, and it never writes a sidecar. Profile resolution is the ordinary resolver. A `.json` or URL profile therefore still goes through the frozen install/cache behavior (A2, G13), exactly as for every other command. There is no transient resolver.
- It must not call `validate_store`, because that function initializes the store. Python extracts a private read-only helper that runs the seven ready checks. `validate_store` calls `initialize()` and then this helper, so its public behavior does not change. TS ports the helper.

Outcomes, keyed on `schema_info()` (missing path = `uninitialized` in `schema_info`, reported here as `missing`). The exit code is 0 if and only if `passed` is true (Q2).

| Store | stdout (key order as listed) | exit |
|---|---|---|
| path absent | `{"schema":"memory-core-doctor/v2","state":"missing","passed":false,"action":"init"}`; no file is created | 1 |
| `legacy-v2` / `legacy-v3` / `legacy-v4` | `schema`, `state`, `passed:false`, `action:"migrate-to"` | 1 |
| `unknown` (an existing file that is neither recognized nor foreign/future, e.g. an empty SQLite) | `{"schema":…,"state":"unknown","passed":false}`, with no `action`, since `init` does not accept it; fail closed | 1 |
| `incompatible` | the existing `SchemaVersionError` on stderr | 1 |
| WAL mode or a WAL sidecar | the existing `IncompatibleJournalMode` on stderr; directory and file bytes untouched | 1 |
| `ready` | `schema`, `state:"ready"`, `passed`, `checks`, `foreign_key_errors` | 0 if passed, else 1 |

On `ready`, `checks` holds exactly these seven names, in this order: `integrity_ok`, `foreign_keys_ok`, `one_current_revision_per_record`, `no_orphan_current_revision`, `relations_carried_to_event_stream`, `schema_application_id`, `schema_version_current`.

**P11 — CLI reads never create a store (test-only).** `status`, `retrieve`, `timeline`, `core-proposals` and `work` follow the R2c P9 rule: on a missing or uninitialized store they give their typed result or error, and no file appears. `retrieve` with tracking on a ready store still writes, as on MCP. `apply-receipt` keeps its R2a behavior. A8 shows that Python already behaves this way, so the corpus pins the behavior and neither runtime may regress.

**P12 — `.last-profile` after a successful resolve only (frozen invariant, test-only).** Python `resolve()` already calls `remember(chosen)` only after `load_profile` succeeds. A failed resolve leaves the previous value untouched. The corpus pins this, and TS ports it exactly; Python does not change.
- `profiles` does not resolve, so it never touches `.last-profile`. `plugin` (R2e) behaves the same way.
- `doctor` resolves with `remember_choice=False`.
- Usage and help never resolve.

**P13 — deterministic public CLI errors (semantic oracle patch).** Today every exception other than `SystemExit` and `_settle` escapes as a traceback (A13). P13 changes that:
- After argparse parsing, profile resolution and command execution run inside one handler.
- A **public** error prints exactly `<PyName>: <message>\n` to stderr and exits 1. `<PyName>` is `type(exc).__name__`, so a subclass prints its own name (for example `MigrationRequiredError`, `PinnedRecordError`).
- `SystemExit` passes through unchanged. `_settle` keeps its special order: the receipt id goes to stderr first, then the typed line.
- Any other exception keeps A13: exit 1, a non-empty stderr, and traceback text that is not frozen. Generic `RuntimeError` is **not** caught, so internal bugs never look public.
- The public set, matched with `isinstance`:
  - authority errors: `HumanPresenceRequired`, `ConfirmationMismatch`, `ReceiptNotFound`, `ReceiptIntegrityError`, `ProposalIntegrityError`, `ProposalDecided`, `StaleAuthority`;
  - store errors: `SchemaVersionError`, which covers `MigrationRequiredError` and `IncompatibleJournalMode`;
  - `PinnedRecordError`, `WorkStoreError`, `FileExistsError`, `ValueError`.
- TS error classes map to these Python wire names exactly, extending the R2c §5.4 map: for example, TS `MigrationRequired` prints `MigrationRequiredError`.
- The corpus pins one scenario per public name that the in-scope commands can raise, plus one untyped crash, for which only the exit code and a non-empty stderr are checked.

G13 (A2, silent profile overwrite) is **frozen** until R4 (Q3). Both runtimes keep the overwrite. An explicit corpus case, inside the scenario temp root, proves that a same-name profile with different `.json` or URL contents overwrites the installed one. TS therefore cannot quietly choose a "safer" behavior and diverge.

## 3. Command-line contract

### 3.1 Parsing (Q4)
- The grammar is the argparse grammar in `cli.py`: the same global options, commands, positional arguments, flags, defaults and mutually exclusive groups.
- Integer options (`--limit`, `--budget`) follow Python 3.11 `int(token)` (base 10) exactly, as argparse calls it. That means:
  - surrounding Python whitespace;
  - one optional ASCII `+` or `-`;
  - any Unicode decimal digit (Nd), for example `١٢`, `１２` and `१२` are all 12;
  - `_` only singly, between two digits.
  
  Anything else is a usage error. TS decides digits and whitespace from frozen Python 3.11 / Unicode 14 tables shipped in `spec/golden-cli-v1/` (`decimal.json`: each Nd code point with its value, as ranges; `whitespace.json`: the code points `str.strip()`/`int()` treat as whitespace). Like `isalnum.json`, each table pins its schema, `unicode: "14.0.0"`, generator provenance and a SHA-256 digest, and is re-derived by an exhaustive Python test. Node's own Unicode data and regex classes are not the law.
- Frozen (Q4): a usage error exits 2, and the **last non-empty stderr line** starts with exactly `trajecta-identity: error:` (argparse prints the usage first; it is not patched). `-h` / `--help` exits 0. The usage and help prose before it is not frozen. Usage and help **write nothing**: no profile, store, data-dir or `.last-profile` change.
- Not frozen: the usage and help paragraphs.

### 3.2 Output
- stdout: `pythonIndentedJson(result)` + `\n`, with `default=str` handled for the value kinds the commands can return (paths as their native string).
- `retrieve --packet`: the packet bytes, no newline.
- stdout and stderr are UTF-8 with Python `errors="replace"` encode semantics: a lone surrogate becomes the literal byte `?` (0x3F), never U+FFFD. stdin is decoded strictly.

### 3.3 `setup` (Q5)
- The config is compared field for field. The only normalization is the known launcher prefix, matched exactly:
  - Python: `command = sys.executable`, `args` starts `["-m", "trajecta_identity.mcp_server"]`.
  - TS: `command = process.execPath`, `args` starts `["--experimental-strip-types", <absolute path of node/src/mcp.ts>]`.
- Everything from `--profile` onward must match exactly: the canonical `profile.name`, the optional resolved `--db`, the server name, the JSON shape and key order.
- The matcher strips exactly those two elements, or fails. No general "ignore the args prefix" rule may hide an extra flag.
- The stderr hint is frozen byte for byte.

### 3.4 Errors and exit codes
- `SystemExit(text)` keeps its current behavior: it prints `text\n` to stderr and exits 1.
- Public typed errors print exactly `<PyName>: <message>\n` to stderr and exit 1, as defined by P13 (§2). They are byte-exact.
- `_settle` (A6) is byte-exact on both streams.
- Untyped crashes (A13) exit 1 with a non-empty stderr. The text is not frozen.

### 3.5 Owner authority on a terminal (Q6, F7)
- The `Terminal` is built from the real process: `stdinTTY = process.stdin.isTTY === true`, `stdoutTTY = process.stdout.isTTY === true`. The prompt goes to stdout, and the reply is one line read from stdin.
- Non-TTY refusal is byte-exact and runs on every OS.
- The injected `Terminal` is the cross-platform contract proof (R2a), Windows included.
- One real pseudo-terminal smoke per approve command runs on Linux and macOS only, with OS-specific `script` invocations (util-linux and BSD flags differ). It sends no malformed bytes.
- Invalid UTF-8 in a confirmation reply: the strict decode failure is caught at the confirmation boundary and rethrown as `ConfirmationMismatch("confirmation input was not valid UTF-8")`. The public CLI line is `ConfirmationMismatch: confirmation input was not valid UTF-8`, and no receipt is issued or consumed. One injected-terminal raw-input test pins this in both runtimes. It is never a crash.

### 3.6 Profiles and paths (F3)
- `safeFsName` decides "alphanumeric" from a **frozen table**, never from the runtime's Unicode data. TS does not use ICU or `\p{…}` property escapes for the decision.
- `spec/golden-cli-v1/isalnum.json` is the complete Python 3.11 / Unicode 14.0.0 truth: every non-surrogate code point for which `str.isalnum()` is true, as compact ranges. It pins its schema name, `unicode: "14.0.0"`, generator provenance and a SHA-256 digest.
- An exhaustive Python 3.11 test re-derives the table. A list of code points where Node's own data disagrees may ship as review metadata only; it is never consulted at runtime.
- `strip(". ")`, the Windows reserved-name rule and the `default` fallback are ported exactly.
- URL profiles: `fetch` with a 20 s timeout, `User-Agent: trajecta-identity-memory`, a 256 KiB cap (read at most 256 KiB + 1), strict UTF-8, and the same `_check` messages. Only `http:` and `https:` are accepted.

### 3.7 `migrate-to` (F6)
- Source missing with `--dry-run`: `{"state":"ready","from":"uninitialized","dry_run":true}`, and nothing is written.
- Source missing, real run: a fresh ready target is created, with **no** backup.
- Legacy source, real run:
  - the backup is byte-identical to the source and inherits its mtime (`copy2`; TS uses `copyFileSync` followed by `utimesSync`);
  - the final target's mtime is not required to equal the source's, because SQLite mutates the copy;
  - refusals come in this order: target exists, then backup exists;
  - a failed migration removes the target;
  - the source and the backup are never modified after the backup is created.
- Dry run on a legacy source: the rehearsal happens in a temporary sibling folder, and no output is left behind.
- The migrated copy is compared through the R0 dump, and the backup by bytes.

## 4. Isolation by construction (hard rule, F5)
- No CLI corpus child runner (Python generator, TS replay, unit tests) uses `os.environ.copy()`, `{...process.env}` or any inherited environment. The child env starts from an explicit allowlist: `PATH`, plus `SYSTEMROOT` and `COMSPEC` on Windows, plus the scenario's own variables.
- On every scenario, `HOME`, `USERPROFILE`, `XDG_DATA_HOME`, `LOCALAPPDATA`, `APPDATA`, `TRAJECTA_IDENTITY_DATA_DIR` and `TRAJECTA_IDENTITY_PROFILES` point inside the scenario temp root.
- `TRAJECTA_WORK_ROOT` is absent unless the scenario sets a temp-rooted value. `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` and `NO_PROXY` (any case) are never inherited.
- The URL test server binds loopback only, on an ephemeral port.
- Every argv path that can be written (db, target, backup, out, profile install destination) is resolved and asserted to be under the scenario temp root **before** the child runs.
- The bundled `example` profile is copied into the temp `PROFILES` folder. Children never receive the repo `profiles/` folder as a writable profile root.
- These checks are the proof of isolation. The extra check that the runner's own real data-dir path never reached a child stays as a backstop.

## 5. Corpus and tests

`tools/golden_cli/generate.py` → `spec/golden-cli-v1`. Each scenario has:
- `argv.json`, `env.json` (relative paths only), `stdin` bytes, `tty` flag;
- an oracle-generated `fixture/` (data dir, profiles, work root, store);
- the expected `exit`, `stdout`, `stderr` bytes (or `stderr.prefix` where §3 does not freeze the text);
- the post-run file tree with hashes, and the R0 dump of each store, or its absence.

Scenarios cover at least the following.
- **Commands in scope:** each one on an absent, an uninitialized, a `legacy-v4` and a ready store.
- **Reads, usage and help:** every one of these scenarios asserts that the DB is absent (where it started absent) and that there are no activation, `-wal` or `-shm` sidecars.
- **Resolve:** every branch (name, folder, `.json`, URL against the loopback server, env, `.last-profile`, default). A failed resolve leaves `.last-profile` unchanged (P12). `profiles` leaves it untouched.
- **G13:** a same-name profile with different `.json` and URL contents overwrites the installed one, inside temp.
- **`safe_fs_name`:** reserved names, dots, spaces, non-ASCII letters and digits.
- **`retrieve`:** `--packet`, `--readonly`, `--history`.
- **Integer options:** Arabic-Indic, fullwidth and Devanagari digits; valid and invalid `_` placement; surrounding Unicode whitespace; `+` and `-`; a non-decimal digit such as `²`, which must be a usage error.
- **Approve commands:** `--issue-only`, inline consume success and failure for each one, and non-TTY refusal.
- **`migrate-to`:** every F6 branch, plus an existing target, an existing backup, and a v2, v3 and v4 source.
- **`doctor`:**
  - each F1 row: absent, an existing empty or unknown SQLite, v2/v3/v4, ready pass, ready with a forced check failure, foreign/future, and a WAL sidecar;
  - every refusal and read path proves that the file tree, including sidecars, did not change.
- **`work`:** with and without a work store, and `TRAJECTA_WORK_ROOT` precedence (as in R2c).
- **Output encoder (F4):**
  - a synthetic lone surrogate goes through the output helper, at unit level, in both runtimes, and comes out as `?`;
  - any end-to-end case uses a non-memory surface, for example a profile manifest listed by `profiles`;
  - no store may hold an R0-invalid value.

The corpus is byte-identical under PYTHONHASHSEED 0/1/4294967295 in the pinned container, and CI checks it with a **full** diff that includes MANIFEST.
