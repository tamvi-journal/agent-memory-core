# R2d: TypeScript owner CLI

Status: draft for Lam's review. Author: Aux (leader). Builds on R0, R2a, R2b and R2c.

## 0. Goal, scope, dependency

R2d gives `@trajecta/identity` a command-line entry point that can stand in for `trajecta_identity/cli.py` (`trajecta-identity`). Python stays the oracle. As in R2c, the port must first **define** what the Python CLI does today (§1). Oracle patches (P10–P12) then fix the few places where that behavior is unsafe or undefined, in both runtimes, and the TS port follows the patched oracle.

**F0 — dependency.** R2d starts from a `main` that contains PR #18 (65e374d). The CLI reuses the R2c `IdentityMemory`, profile loading, `pythonIndentedJson` and the error classes. It must not fork them.

**In scope (Q1 = split, recommended)**
- Entry point `node --experimental-strip-types node/src/cli.ts [-p PROFILE] [--db PATH] COMMAND …`, with no dependencies.
- Profile resolution (`recipe.resolve`): name, folder, `.json` file, `http(s)` URL; `$TRAJECTA_IDENTITY_PROFILE`; `.last-profile`; default `example`.
- Paths: `data_dir`, `safe_fs_name`, `profile_db`, `profile_search_dirs`.
- Commands: `init`, `setup`, `profiles`, `work`, `status`, `retrieve`, `log-phase`, `log-fact`, `timeline`, `decay`, `core-proposals`, `approve-core`, `approve-retract`, `close-legacy-discussion`, `apply-receipt`, `close-loop`, `migrate-to`, and the new `doctor` (P10).

**Out of scope**
- **R2e (Q1):** `view` (HTTP server and page), `plugin` (bundle builder), `import-aml`. Each one is a separate surface with its own I/O (sockets, zip, a foreign SQLite file), and none is on the cutover path.
- **R3:** cross-runtime runs, fuzzing (carry: present-null or non-string evidence metadata at the kernel, and `source_ref` null), migration rehearsal on a copy of a real store.
- **R4:** installer, `bin` launcher, cutover, and the single version source (carry: pyproject 0.4.0 vs runtime/wire 0.1.0).
- G1–G12 stay frozen. G6 is fixed on the CLI path by P10 (`doctor`) and P11 (reads).

## 2. Oracle patches (both runtimes)

**P10 — `doctor` that never initializes.** New command `doctor`. It opens the file read-only (`mode=ro`), never creates, migrates or bootstraps it, and never writes a sidecar.
- Missing file: `{"schema":"memory-core-doctor/v2","state":"missing","passed":false}`.
- `uninitialized` or any `legacy-*` state: `{"schema":…,"state":…,"passed":false,"action":"init"|"migrate-to"}`. No checks are run.
- `newer` or foreign file: the existing `SchemaVersionError`, exit 1.
- `ready`: the seven `validate_store` checks, in the same order and with the same names, plus `"state":"ready"` and `foreign_key_errors`.
- Exit code: 0 when `passed` is true, 1 otherwise (Q2).
- `validate_store` itself is unchanged for its other callers.

**P11 — CLI reads never create a store.** `status`, `retrieve`, `timeline`, `core-proposals` and `work` follow the R2c P9 rule: on a missing or uninitialized store they report the same typed result or error the MCP read tools give, and no file appears. `retrieve` with tracking enabled on a ready store still writes, as on MCP. `apply-receipt` keeps its R2a behavior. A8 shows that Python already behaves this way, so P11 is a test-only patch: the corpus pins it so neither runtime can regress.

**P12 — `.last-profile` only after a successful resolve.** It is written only after the profile has loaded and validated, and never by `doctor`. Read commands keep writing it (it is a convenience file, not memory). A failed resolve leaves the previous value untouched.

G13 (A2, silent profile overwrite) is **frozen** in R2d and recorded in the gap table (Q3). Both runtimes keep the overwrite, so the port does not diverge.

## 3. Command-line contract

### 3.1 Parsing
- The grammar is the argparse grammar in `cli.py`: the same global options, commands, positional arguments, flags, defaults and mutually exclusive groups.
- Integer options (`--limit`, `--budget`) accept what Python `int()` accepts after argparse: optional sign, ASCII digits, surrounding whitespace, and `_` separators between digits. Anything else is a usage error.
- Usage errors exit 2. Only the exit code and the first stderr line prefix `trajecta-identity: error:` are frozen. The usage and help text are **not** a byte contract (Q4).
- `-h` / `--help` exits 0. The text is not frozen.

### 3.2 Output
- stdout: `pythonIndentedJson(result)` + `\n`, with `default=str` handled for the value kinds the commands can return (paths as their native string).
- `retrieve --packet`: the packet bytes, no newline.
- `setup`: stdout carries the JSON config. The command is the runtime's own (`process.execPath` and `[--experimental-strip-types, <abs path to mcp.ts>, --profile, …]` in TS). The corpus compares everything except `command` and the module or script prefix of `args` (Q5). The stderr hint is frozen byte for byte.
- stdout and stderr are UTF-8. A lone surrogate is written as `?` (A3). stdin is decoded strictly; invalid UTF-8 in a TTY confirmation is a confirmation failure, never a crash.

### 3.3 Errors and exit codes
- Typed failures that Python raises as `SystemExit(text)` or that escape as one of the error classes in R2c §5.4 print `Name: message\n` (or the plain SystemExit text) to stderr and exit 1. These are byte-exact.
- `_settle` (A6) is byte-exact on both streams.
- Untyped crashes (A13) are exit 1 with a non-empty stderr. The text is not frozen.

### 3.4 Owner authority on a terminal
- The `Terminal` is built from the real process: `stdinTTY = process.stdin.isTTY === true`, `stdoutTTY = process.stdout.isTTY === true`. The prompt goes to stdout, and the reply is one line read from stdin.
- Non-TTY refusal is byte-exact (R2a).
- The TTY path is tested in two ways: (a) the authority corpus, through the injected `Terminal`, as in R2a; (b) one real pseudo-terminal smoke per approve command on Linux and macOS (`script`). There is no Windows TTY smoke (Q6).

### 3.5 Profiles and paths
- `safeFsName` must match Python `str.isalnum()` per code point, not `\w`. The table is generated from Python 3.11 into `spec/golden-cli-v1/isalnum.json` (code points where the two runtimes' Unicode data disagree are listed and pinned to the Python answer).
- `strip(". ")`, the Windows reserved-name rule and the `default` fallback are ported exactly.
- URL profiles: `fetch` with a 20 s timeout, `User-Agent: trajecta-identity-memory`, a 256 KiB cap (read at most 256 KiB + 1), strict UTF-8, and the same `_check` messages. Only `http:` and `https:` are accepted. The tests use a local HTTP server; no test touches the network.

### 3.6 `migrate-to`
- Port A10 exactly. That includes the mtime-preserving copy (`fs.copyFileSync` followed by `utimesSync` from the source), the refusal order (target, then backup), `.v{n}.bak`, the dry run in a temporary sibling folder, and the cleanup of the target on failure.
- The migrated copy and the backup are compared through the R0 dump and by bytes, respectively.

## 4. Isolation (hard rule, after the R2c boundary incident)

- Every runner (Python generator, TS replay, unit tests) builds the child environment **from an allowlist**, never from `process.env` / `os.environ`. The allowlist is `PATH`, `SYSTEMROOT` and `COMSPEC` on Windows, plus the scenario's own variables.
- `HOME`, `USERPROFILE`, `XDG_DATA_HOME`, `LOCALAPPDATA`, `APPDATA`, `TRAJECTA_IDENTITY_DATA_DIR` and `TRAJECTA_IDENTITY_PROFILES` always point inside the scenario's temporary folder, even when the scenario does not use them.
- A test asserts that, after each scenario, nothing outside the temporary folder changed. It does this by checking that the real data dir path given by the runner's own environment was never passed to a child.

## 5. Corpus and tests

`tools/golden_cli/generate.py` → `spec/golden-cli-v1`. Each scenario has:
- `argv.json`, `env.json` (relative paths only), `stdin` bytes, `tty` flag;
- an oracle-generated `fixture/` (data dir, profiles, work root, store);
- the expected `exit`, `stdout`, `stderr` bytes (or `stderr.prefix` where §3 does not freeze the text);
- the post-run file tree with hashes, and the R0 dump of each store, or its absence.

Scenarios cover at least the following:
- every command in scope, on a missing, an uninitialized, a `legacy-v4` and a ready store;
- every resolve branch (name, folder, `.json`, URL against a local server, env, `.last-profile`, default), including a failed resolve (P12);
- `safe_fs_name` edge cases (reserved names, dots, spaces, non-ASCII letters and digits);
- `retrieve --packet`, `--readonly`, `--history`;
- `--issue-only`, inline consume success and failure for each approve command, non-TTY refusal;
- `migrate-to`: real run, dry run, existing target, existing backup, a missing source, and a v2/v3/v4 source;
- `doctor` in each P10 state, plus a ready store with a forced check failure;
- `work` with and without a work store, and `TRAJECTA_WORK_ROOT` precedence (as in R2c);
- usage errors (exit 2, prefix only);
- a lone surrogate in a record title, printed by `status`/`timeline` (A3).

The corpus is byte-identical under PYTHONHASHSEED 0/1/4294967295 in the pinned container, and is checked in CI with a **full** diff including MANIFEST.
